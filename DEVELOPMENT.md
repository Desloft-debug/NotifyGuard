# Разработка

Android 14 (targetSdk 34, minSdk 29), Kotlin + Jetpack Compose.

Скрывает рекламные уведомления, оставляет коды подтверждения, операции по счёту и экстренные сообщения. Отдельным переключателем приглушает звонки с номеров, которых нет в контактах.

## Сборка

Открыть папку в Android Studio (Ladybug или новее) и нажать Run. Из командной строки:

```
gradle wrapper          # один раз, если нет gradlew
./gradlew assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/`.

## Первый запуск

1. **Чтение уведомлений** — экран «Доступ» → «Открыть настройки» → включить «Тихие уведомления» в списке. Без этого фильтр не работает.
2. **Контакты** — разрешить доступ, иначе все номера считаются знакомыми и ничего не приглушается.
3. **Проверка звонков** — «Назначить», система спросит, сделать ли приложение приложением для проверки вызовов.

## Как принимается решение

Порядок проверок в `FilterRules.decide()`, сверху вниз:

1. Системные пакеты — телефон, будильник, экстренные оповещения, менеджеры питания прошивок.
2. Категории `CATEGORY_CALL`, `ALARM`, `EVENT`, `REMINDER`, `SYSTEM`, `ERROR`, `STATUS` и несъёмные уведомления.
3. Экстренные оповещения по словам (МЧС, evacuation, Unwetter, NINA).
4. Состояние устройства: заряд, память, перегрев.
5. **Слова-исключения пользователя** — пропускаем.
6. **Стоп-слова пользователя** — скрываем. Идут раньше проверки кодов и сумм, поэтому «кредит» сработает даже на уведомлении с рублями. Это осознанно: слово, которое человек вписал сам, должно перебивать эвристику.

   До версии 3.1 приложение при первой установке само записывало в этот список девять слов — «акции», «деньги», «займы», «кредит», «обновление», «подписка», «процент», «рекомендации», «скидка». Правило «слово пользователя главнее» относилось к словам, которых пользователь не выбирал, и из-за этого терялись смс банка («Кредит одобрен, код 4821»), начисления по вкладу и личные сообщения со словом «скидка». Все девять уже покрыты словарём `PROMO_RU` в формах, которые не задевают банковские тексты, поэтому засев убран. `Prefs.migrate()` удаляет старый набор, если он не тронут; всё, что добавлено руками, остаётся.
7. Чёрный и белый списки приложений.
8. Коды подтверждения.
9. Операции по счёту.
10. Рекламные слова.
11. Если ничего не совпало: строгий режим скрывает, обычный пропускает.

### Границы слов

Слово ищется по началу: перед ним не должно стоять буквы или цифры, продолжение допускается. `скидк` ловит «скидки» и «скидка», `код` ловит «кодом», но **не** срабатывает внутри «промокод». Раньше этой проверки не было, и рекламные рассылки со словом «промокод» проходили как коды подтверждения.

Живёт это в `WordMatch.contains()` — обычный `indexOf` в цикле с проверкой символа слева. До 3.1 то же самое делалось регуляркой `(?<![\p{L}\p{N}])` + `Regex.escape(needle)` со словарём скомпилированных шаблонов в `ConcurrentHashMap`, из которого ничего не выселялось. Смысл был тот же, но на одно уведомление приходится несколько сотен таких проверок в главном потоке, а кеш рос вместе с онлайн-словарём.

`WordMatch` вынесен из `FilterRules` отдельным объектом ещё и потому, что `FilterRules` при инициализации трогает константы `android.app.Notification` — тесты пришлось бы гонять через Robolectric. В `WordMatch` зависимостей от Android нет.

### Чего нет в списке денег

Символы валют (`₽`, `€`, `руб`) намеренно убраны из списка банковских слов. С ними любая реклама с ценником — «Смартфон за 19 990 ₽», «Доставка от 299 ₽» — считалась операцией по счёту и пропускалась. Теперь нужны глаголы операций: перевод, зачислено, списано, оплата, баланс.

По той же причине в списке нет голого «начислен»: под него попадают бонусные рассылки («вам начислено 500 бонусов»), а рекламный словарь проверяется позже банковского. Вместо него — только `начислен процент` и его формы: проценты по вкладу не ловились вообще ничем.

### Причины в журнале

`FilterRules.decide()` возвращает `Verdict` с кодом `ReasonCode` и словом-триггером, а не готовой строкой. В журнал уходит `verdict.encode()` — код и слово через служебный разделитель, текст собирается в `ReasonText.render()` уже на языке интерфейса. До 3.1 причина собиралась русским текстом прямо в `FilterRules`, и у пользователя с английским интерфейсом весь журнал оставался на русском. Записи, сделанные старыми версиями, `render()` распознаёт по отсутствию кода и показывает как есть — миграция журнала не нужна.

## Видимость пакетов

В манифесте есть блок `<queries>` с intent на launcher-активность и поимённым списком вендорских пакетов. Без него на Android 11+ `getApplicationInfo()` бросает `NameNotFoundException` почти для всех чужих пакетов, и в журнале вместо «WhatsApp» видно `com.whatsapp`; `pm.resolveActivity()` для экранов автозапуска Xiaomi и Huawei возвращает `null`, и кнопка «Автозапуск» не показывается.

`QUERY_ALL_PACKAGES` намеренно не используется: F-Droid и IzzyOnDroid помечают его как anti-feature, а intent на launcher закрывает ту же задачу — видны все приложения со значком в меню, то есть ровно те, чьи уведомления человек может увидеть. Список вендорских пакетов в `<queries>` должен совпадать с `KeepAlive.VENDOR_SCREENS`.

## Тесты

```
./gradlew test
```

`app/src/test` — чистый JUnit без Robolectric и моков, ни один тест не трогает Android:

- `WordMatchTest` — границы слов;
- `DictionarySafetyTest` — главный смысловой тест: коды подтверждения, операции по счёту, доставка и экстренные оповещения не попадают под рекламный словарь. Плюс проверки самих словарей на дубликаты, регистр и пересечение промо с защитными списками;
- `UpdaterVersionTest` — сравнение версий;
- `NumberLookupTest` — разбор номера.

Словари правятся чаще всего остального, а цена ошибки — потерянный код из банка. Если правка словаря роняет `DictionarySafetyTest`, это не придирка теста.

## Ограничение перехвата

`GuardNotificationListener` снимает уведомление уже после публикации, поэтому баннер может мигнуть на долю секунды перед исчезновением. Погасить уведомление до показа умеет только `NotificationAssistantService`, но это системный API (`@SystemApi`): он недоступен обычным приложениям и не компилируется с публичным SDK. Обойти это без системной подписи нельзя.

## Про звонки

`GuardCallScreeningService` вызывает `setSilenceCall(true)` — рингтон и вибрация отключаются, но звонок не сбрасывается, остаётся в журнале вызовов и в пропущенных. Экстренные вызовы система через скрининг не проводит.

Роль проверки вызовов одна на устройство: пока её держит это приложение, другие определители номера работать не будут.

## Что стоит знать

- Приложение не читает SMS через `READ_SMS` — оно смотрит только текст уведомлений. Разрешение на чтение SMS Google Play выдаёт единицам, а для этой задачи оно не нужно.
- Уведомления никуда не отправляются, весь разбор идёт на устройстве, журнал хранится в `SharedPreferences`.
- Фильтр по словам ошибается на редких формулировках. Журнал «Что было скрыто» показывает каждое снятое уведомление с причиной — по нему удобно добавлять приложения в белый список.
- Банковское приложение лучше сразу занести в белый список, а его промо отключить внутри самого банка: так ни один перевод точно не потеряется.

## Выпуск релиза

Workflow `.github/workflows/release.yml` собирает APK и публикует релиз при отправке тега:

```
git tag v1.0
git push origin v1.0
```

Через веб-интерфейс: Releases → Draft a new release → Choose a tag → впишите `v1.0` → Create new tag on publish → Publish release. Сборка запустится сама и прикрепит APK к релизу через пару минут.

Релизный APK подписывается ключом из секрета `KEYSTORE_BASE64` — как это устроено, описано в следующем разделе. Отладочным ключом подписан только `assembleDebug` из `build.yml`; такой APK не встанет поверх релизного.

## Подпись релизов

Android не использует внешние центры сертификации: ключ самоподписанный, создаётся один раз и хранится у автора. Главное следствие — APK, подписанные разными ключами, не обновляются поверх друг друга.

### Создание ключа

```
keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias notifyguard
```

`keytool` входит в состав JDK; на Windows он лежит в `C:\Program Files\Java\jdk-17\bin` или внутри Android Studio в `jbr\bin`.

Файл `release.jks` и пароли к нему нельзя терять и нельзя коммитить в репозиторий. Потеря ключа означает, что обновить установленное приложение уже не получится — только удалить и поставить заново.

### Передача ключа в CI

```
certutil -encode release.jks release.txt      # Windows
base64 -w0 release.jks                        # Linux/macOS
```

Полученную строку положить в Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | содержимое base64 без переносов строк |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `notifyguard` |
| `KEY_PASSWORD` | пароль ключа |

`release.yml` восстанавливает файл из секрета во временный каталог раннера, собирает `assembleRelease` и удаляет ключ после сборки.

### Выпуск

```
git tag v1.0
git push origin v1.0
```

Через веб: Releases → Draft a new release → Choose a tag → `v1.0` → Create new tag on publish → Publish release.
