# Разработка

Kotlin + Jetpack Compose, minSdk 29, targetSdk 34. Ни аналитики, ни сторонних SDK — из зависимостей только AndroidX и WorkManager.

Приложение скрывает рекламные уведомления, оставляет коды подтверждения, операции по счёту и экстренные сообщения. Отдельным переключателем приглушает звонки с номеров вне контактов.

## Сборка

Открыть папку в Android Studio (Ladybug или новее) и нажать Run. Из консоли:

```
gradle wrapper          # один раз, если нет gradlew
./gradlew assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/`.

## Первый запуск

1. **Чтение уведомлений** — «Доступ» → «Открыть настройки» → включить «Тихие уведомления» в списке. Без этого фильтр не работает вообще.
2. **Контакты** — без разрешения все номера считаются знакомыми и ничего не приглушается.
3. **Проверка звонков** — «Назначить», дальше система сама спросит.

## Что где лежит

Пакет один, файлы разложены по смыслу:

| Файл | Про что |
|---|---|
| `FilterRules.kt` | правила: `NotificationInput`, `Snapshot`, `Verdict`, порядок проверок |
| `WordMatch.kt` | поиск слова с проверкой границы слева |
| `Dictionaries.kt` | встроенные словари, защитные и рекламные |
| `RemoteDictionary.kt` | словарь из репозитория, синхронизация и разбор |
| `Prefs.kt` | настройки, миграции, снимок для фильтра |
| `GuardLog.kt` | журнал уведомлений и звонков |
| `GuardNotificationListener.kt` | слушатель уведомлений |
| `GuardCallScreeningService.kt` | приглушение звонков |
| `KeepAlive.kt`, `GuardForegroundService.kt` | чтобы процесс не выгружали |
| `Updater.kt` | обновление из GitHub Releases |
| `Backup.kt` | копия настроек в файл |
| `MainActivity.kt` | каркас: вкладки, тема, язык, первый запуск |
| `ProtectScreen.kt`, `DictScreen.kt`, `LogScreen.kt`, `HelpScreen.kt` | вкладки |
| `UiKit.kt`, `NumberDialog.kt`, `SystemActions.kt` | общие кусочки UI и всё, что дёргает систему |
| `Strings.kt`, `Lang.kt`, `ReasonText.kt`, `Theme.kt` | тексты, язык, оформление |

Экраны читают настройки напрямую из `Prefs` — ViewModel тут нечего хранить, всё состояние и так лежит в `SharedPreferences`. Перечитывание завязано на счётчик `refresh`, который увеличивается на `onResume`: из системных настроек человек возвращается с уже другими разрешениями.

## Порядок правил

`FilterRules.decide()`, сверху вниз:

1. Системные пакеты — телефон, будильник, экстренные оповещения, менеджеры питания прошивок.
2. Категории `CATEGORY_CALL`, `ALARM`, `EVENT`, `REMINDER`, `SYSTEM`, `ERROR`, `STATUS` и несъёмные уведомления.
3. Экстренные оповещения по словам (МЧС, evacuation, Unwetter, NINA).
4. Состояние устройства: заряд, память, перегрев.
5. **Слова-исключения пользователя** — пропускаем.
6. **Стоп-слова пользователя** — скрываем.
7. Чёрный и белый списки приложений.
8. Личные сообщения (`MessagingStyle`).
9. Доставка, коды подтверждения, операции по счёту.
10. Онлайн-словарь и рекламные слова.
11. Ничего не совпало: строгий режим скрывает, обычный пропускает.

Пункт 6 стоит выше кодов и сумм сознательно: слово, которое человек вписал сам, должно перебивать любую эвристику. Обратная сторона — стоп-слово `кредит` съест и «Кредит одобрен, код 4821». В справке про это написано прямым текстом.

Порядок закреплён тестом `FilterRulesTest`, так что переставлять проверки «просто так» не выйдет.

### Границы слов

Слово ищется по началу: слева не должно быть буквы или цифры, продолжение свободное. `скидк` ловит «скидки» и «скидка», `код` ловит «кодом», но не срабатывает внутри «промокод» — иначе рекламные рассылки с промокодами проходили бы как коды подтверждения.

`WordMatch` живёт отдельным объектом ещё и потому, что `FilterRules` при инициализации трогает константы `android.app.Notification`. В `WordMatch` зависимостей от Android нет совсем.

### Чего нет в словарях

Символов валют (`₽`, `€`, `руб`) в списке банковских слов нет: с ними любая реклама с ценником — «Смартфон за 19 990 ₽» — считается операцией по счёту. Нужны глаголы: перевод, зачислено, списано, оплата, баланс.

Голого «начислен» там нет по той же причине — «вам начислено 500 бонусов» это рассылка, а не банк. Оставлено только «начислен процент» и формы.

Пересечения промо и защитных словарей ловит `DictionarySafetyTest`.

### Причины в журнале

`decide()` возвращает `Verdict` с кодом и словом-триггером, а не готовую фразу. В журнал уходит `verdict.encode()`, текст собирает `ReasonText.render()` уже на языке интерфейса — иначе у человека с английским UI журнал оставался бы русским. Записи старого формата `render()` узнаёт по отсутствию кода и показывает как есть, миграция не нужна.

## Журнал

`GuardLog` держит оба списка в памяти под общим замком, на диск пишет из своего однопоточного исполнителя. Пишет в него слушатель (главный поток сервиса), читает и чистит UI — без общего замка порядок операций получается непредсказуемым.

Хранится в `SharedPreferences` обычным JSON. Записей сто, база тут была бы лишней.

## Видимость пакетов

В манифесте есть `<queries>` с intent на launcher-активность и поимённым списком вендорских пакетов. Без него на Android 11+ `getApplicationInfo()` бросает `NameNotFoundException` почти для всех чужих пакетов (в журнале вместо «WhatsApp» видно `com.whatsapp`), а `resolveActivity()` для экранов автозапуска Xiaomi и Huawei возвращает `null`, и кнопка «Автозапуск» не показывается.

`QUERY_ALL_PACKAGES` не используется: F-Droid и IzzyOnDroid помечают его как anti-feature, а intent на launcher закрывает ту же задачу. Список вендорских пакетов в `<queries>` должен совпадать с `KeepAlive.VENDOR_SCREENS`.

## Ограничение перехвата

Слушатель снимает уведомление уже после публикации, поэтому баннер может мигнуть. Гасить до показа умеет только `NotificationAssistantService` — это `@SystemApi`, обычному приложению он недоступен и с публичным SDK не компилируется.

## Про звонки

`setSilenceCall(true)` отключает рингтон и вибрацию, но звонок не сбрасывает: он остаётся в журнале вызовов и в пропущенных. Экстренные вызовы через скрининг система не проводит.

Роль проверки вызовов на устройстве одна: пока её держим мы, другие определители номера не работают.

Поиск по контактам вынесен в отдельный поток — `onScreenCall` приходит в главный, а ответить надо за секунды.

## Обновление

`Updater` ходит в `releases/latest` без токена (60 запросов в час на IP, 403 — это лимит, а не отсутствие сети). Хост проверяется на каждом редиректе, поэтому редиректы разбираются вручную. Скачанный APK проверяется по sha256 из описания релиза, если он там есть, и по подписи — сверкой с установленным пакетом.

## Тесты

```
./gradlew test
```

`app/src/test` — чистый JUnit, ни Robolectric, ни моков:

- `FilterRulesTest` — порядок правил;
- `DictionarySafetyTest` — коды, деньги, доставка и МЧС не попадают под рекламный словарь, плюс проверки самих словарей на дубликаты, регистр и пересечения;
- `WordMatchTest` — границы слов;
- `UpdaterVersionTest` — сравнение версий;
- `NumberLookupTest` — разбор номера.

Словари правятся чаще всего остального, а цена ошибки — потерянный код из банка. Если правка словаря роняет `DictionarySafetyTest`, это не придирка теста.

## Выпуск релиза

Workflow `.github/workflows/release.yml` собирает APK и публикует релиз по тегу:

```
git tag v1.0
git push origin v1.0
```

Через веб: Releases → Draft a new release → Choose a tag → `v1.0` → Create new tag on publish → Publish release. Сборка сама прикрепит APK через пару минут.

Отладочным ключом подписан только `assembleDebug` из `build.yml`, такой APK поверх релизного не встанет.

## Подпись релизов

Ключ самоподписанный, внешних центров сертификации у Android нет. Главное следствие: APK, подписанные разными ключами, не обновляются поверх друг друга.

```
keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias notifyguard
```

`keytool` лежит в JDK: на Windows это `C:\Program Files\Java\jdk-17\bin` или `jbr\bin` внутри Android Studio.

Файл `release.jks` и пароли к нему нельзя терять и нельзя коммитить. Потеря ключа = обновить установленное приложение уже не получится, только удалить и поставить заново.

### Ключ в CI

```
certutil -encode release.jks release.txt      # Windows
base64 -w0 release.jks                        # Linux/macOS
```

Строку положить в Settings → Secrets and variables → Actions:

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | base64 без переносов строк |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `notifyguard` |
| `KEY_PASSWORD` | пароль ключа |

`release.yml` восстанавливает файл во временный каталог раннера, собирает `assembleRelease` и удаляет ключ после сборки.
